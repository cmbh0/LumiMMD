# Lumi MMD

安卓上的 MMD 编辑器：看模型、放动作和音乐、摆姿势打关键帧、在轨道上像剪视频一样排片段、用 Lua 脚本做特效和驱动模型、
用摇杆操控角色走跑跳、从零建模，还能让 AI 通过 MCP 直接操作。Blender 的 `.blend` 场景可以直接当舞台导入。
渲染、动画、物理、建模、特效、MCP 服务都是自己用 Kotlin + OpenGL ES 3.0 写的，没有用 native 库；
Lua 解释器用的是 [LuaJ](https://github.com/luaj/luaj) 3.0.1（纯 Java，MIT 许可）。

- 当前版本 4.2.0，包名 `com.lumi.mmd`，界面语言：中文，横屏竖屏都能用
- 最低 Android 7.0（API 24），需要 OpenGL ES 3.0
- release 包用调试密钥签名（见「构建」）。调试密钥每台电脑各不相同：同一台电脑打出来的包可以互相覆盖安装、资源库和场景会保留；
  换了一台电脑打的包签名不同，装之前得先卸载旧的（要长期更新请换成自己固定的 keystore）

## 下载与安装

最新的安装包在 [Releases](https://github.com/cmbh0/LumiMMD/releases)：`LumiMMD-4.2.0.apk`，约 3.2 MB，
下载后点开安装（系统会问一次是否允许安装未知来源的应用）。

- 签名是调试密钥，和上面说的一样：和手机上已有的包签名不同时，先卸载旧的再装。
- 模型、动作、音乐不在包里，自己放进手机，点右上角「添加」导入。第一次打开有 14 页教程。

代码怎么组织、关键的东西怎么实现、有哪些取舍，另有一份 [ANALYSIS.md](ANALYSIS.md)。

## 4.2 改了什么

| 问题 / 要求 | 做法 |
| --- | --- |
| **MCP 很慢：AI 客户端要等一分钟才连上、才拿到工具清单** | 服务本身不慢（握手和工具清单不碰渲染线程，测试里 20 次 `tools/list` 每次不到 50 毫秒）。慢在**应用被切到后台**：AI 客户端和 Lumi MMD 在同一台手机上时，一切到 AI 客户端，本应用就成了后台应用，系统会暂停或限制它，请求要等系统放行才有人应答；而且后台时渲染线程手里没有 GL 上下文，截图直接失败、要动显存的操作会卡到 25 秒超时。改了四处：① 开着 MCP 时挂一个**前台服务**（`core/McpService.kt`，通知栏有一条「MCP 服务运行中」，带「停止」按钮，同时拿着 CPU 和 Wi-Fi 锁），系统就不会冻结应用；② 后台时渲染线程把保留下来的 GL 上下文**临时接到一块 1×1 的离屏表面上**干活，所以在后台也能截图、建模、加载模型；③ 工具清单只生成一次，以后直接用；④ 面板上显示「收到多少条请求、最近一条处理用了几毫秒」和后台保活的状态，并给了「允许后台运行（不限制电池）」的入口——个别系统即使有前台服务也会冻结后台应用。另外地址列表里多了一个 `127.0.0.1` 的本机地址，AI 客户端在同一台手机上时用它，不经过 Wi-Fi。 |
| **模型要有碰撞属性** | 每个模型多了「碰撞」一项（模型页 →「显示」，三选一）：**无** / **包围盒** / **网格**（按每个三角面，舞台、台阶、桌子用这个；`physics/MeshShape.kt` 给三角面建了一棵包围盒树，几十万面的舞台也查得动）。带碰撞的模型会挡住：别的模型的头发裙子（刚体）、脚本 `sim` 的粒子 / 布 / 水 / 刚体、操控模式里的角色（能站上去、会被墙挡住）、`sim.raycast` / `sim.distance`。形状按没有动作时的样子算，跟着模型的位置 / 旋转 / 缩放走。脚本里是 `m.collision = "mesh"`，MCP 是 `set_model` 的 `collision`。跟着工程保存。 |
| **默认地板要能删、能改、能加回来** | 地板现在是场景里的一个东西（`scene/Floor.kt`），不再是写死的：菜单 →「舞台与背景」→「地板」里可以**删除**（不画网格、不接影子、东西一直往下掉）、**添加默认地板**、改高度、开关网格 / 影子 / 碰撞、改格子大小、换底色（默认是透明的，只有网格和影子）。脚本里是 `floor.set{...}` / `floor.remove()` / `floor.reset()` / `floor.get()`，MCP 是 `floor` 工具。头发裙子、脚本物理、操控的角色、射线查询都跟着地板的高度和有无走。跟着工程保存。 |
| **Lua 支持更多渲染相关的东西，比如三渲二；MCP 也要有** | 新的 `render` 表（原来的 `post.set` 还能用，是同一个函数）：**三渲二**——`render.toon{}` 一句话打开，或者 `render.set{cel=2, cel_soft=, cel_shift=, shade={..}, cel_specular=}` 逐项调（光照分几级、交界线软硬和位置、暗部颜色、硬边高光）；**描边**——粗细、统一颜色、给没有描边数据的 glTF / OBJ / FBX 模型也描（`edge_all`）；影子深浅、边缘光颜色、高光倍数、环境光颜色；画面——对比度、色调分离（`posterize`）、整体调色（`grade`）、背景。单块材质可以单独指定：`mat.cel = false`（脸不要三渲二）、`mat.shading = "unlit"`。脚本改的在脚本停掉时全部复原。MCP 新增 `render` 工具（同一套参数，外加 `preset: "toon"` / `"default"`），AI 改的会留下来并跟着工程保存。菜单 →「灯光与画面」里也有三渲二的开关。新增三个示例：「三渲二」「水墨与漫画」「台阶和地板」。 |

## 4.1.3 改了什么

| 问题 / 要求 | 做法 |
| --- | --- |
| **Lua 脚本的输出为什么清不掉** | 原因有两个。一是只有「控制台」那一页有清空按钮，「脚本」页（平时看输出的地方）没有，MCP 也没有对应的办法，AI 每次读到的都是越积越多的旧输出；二是输出是在渲染线程攒好、隔一会儿才发给界面的，清空时如果正好有一批在路上，刚清掉的行又会被这一批带回来。现在：脚本页加了「清空输出」；清空是连同在路上的那一批一起清（`PlayController.clearLog()`）；MCP 的 `script_log` 多了 `clear` 参数（读完就清，下一次只看到新的）。 |
| **接口说明要写清楚、要实时** | 「接口说明」不再是一段写死的文字。每次打开（或 AI 调 `script_api`）时当场生成（`script/ScriptDoc.kt`）：前面是通用的接口，后面是**场景里现在真有的东西**——每个模型的 id、名字、类型、位置和大小，它真实的骨骼名（标出头 / 手 / 脚这些常用骨骼对应的是哪一根、IK、带物理的）、表情名（按眼 / 口 / 眉分）、材质名、刚体名，时间轴、镜头、物理、已有的脚本和它们的状态。AI 照着抄名字就不会再写出模型里没有的骨骼。`script_api` 可以只看一个模型（`model`）、限制每组列多少个（`limit`）、只要接口不要场景（`scene=false`）、取一个示例的全文（`example`）。 |
| **MCP 支持更多接法** | 原来只有 Streamable HTTP 和旧的 SSE。新加三种，工具和密钥都是同一套：**WebSocket**（`ws://…/ws/<密钥>`，一帧一条 JSON-RPC）；**普通 HTTP 接口**（`GET /api/<密钥>/tools` 拿 OpenAI 函数调用格式的工具清单，`POST /api/<密钥>/tools/<工具名>` 调用，`/api/<密钥>/openapi.json` 是 OpenAPI 3.1 描述——不会 MCP 的程序、Open WebUI 这类「OpenAPI 工具服务器」、自己写的脚本都能用）；**stdio**（桌面版 `--stdio`，客户端把它当子进程起）。详见「让 AI 操作」。 |
| **让 AI 用 Lua 做出任何东西**：重画瞳孔、液体、布料、自己的物理 | 原来脚本只能摆弄已有的东西（骨骼、材质参数、现成的粒子）。现在多了三组「从零造东西」的接口，见下面「脚本 → 自己造东西」：**`canvas`** 一块能画的贴图（渐变、圆、多边形、逐像素、模糊、噪声、把原贴图铺上来），可以换到任何材质上——重画瞳孔就是它；**`mesh`** 自己给顶点和面的网格，每帧能改——任何形状；**`sim`** 自己的物理世界：质点 + 距离约束（XPBD）做绳子、布、软体，PBF 做液体，脚本刚体（和模型头发裙子同一个求解器）、碰撞体、射线和距离查询，以及 `on_step`：每个子步回调一次，脚本在里面自己加力、改速度——内置没有的物理规律自己写。 |

## 4.1.2 改了什么

| 问题 / 要求 | 做法 |
| --- | --- |
| 换应用图标 | 换成了新的图（紫发角色、月亮、底下「LumiMMD」字样）。原来的图标是两张矢量图，现在是位图：`mipmap-*/ic_launcher_foreground.png` 是自适应图标的前景层（108dp，原图正好占中间 72dp——各家桌面能露出的最大范围，圆角方形的桌面上整张图都看得到，四周的出血区用原图边缘延伸出去的模糊背景填满）；圆形图标的桌面（Pixel 等）另有一份 `ic_launcher_round`，原图缩小了一点，底下的字不会被圆边切掉；Android 7.x 用 `ic_launcher.png` / `ic_launcher_round.png`。全部由 `tools/make_icons.py <原图> app/src/main/res` 生成，以后换图重新跑一遍即可。原来的矢量图删掉了，所以 Android 13 的「主题图标」（单色）不再提供。 |
| **MCP 服务别的 AI 客户端连不上 / 拿不到工具清单** | 用官方的 Python SDK、TypeScript SDK（新旧两代）、MCP Inspector、mcp-remote 和官方的一致性测试对着原来的服务跑了一遍，找到四类问题，都改了，详见下面「让 AI 操作（MCP）」里的「兼容性」。① **工具的参数表有 48 处写法很多客户端不收**：29 个工具里「序号或名字」的参数类型写成了 `["integer","string"]`，4 个参数没写类型，`physics` 的 `set` 是一个空的对象，`mesh_op` 的说明超过了 1024 个字符。客户端要把参数表转成 OpenAI / Gemini 这些模型的函数声明，其中一个工具不合格，整份清单都会被拒收——这正是「连上了却拿不到工具」。现在参数表只用各家都认的写法（每个参数一个类型，序号写成 `"3"` 这样的字符串，实际收到整数也照样认）。② **只会新协议的客户端连不上**：MCP 现行的版本是 2026-07-28（无状态，没有握手，用 `server/discover` 查询服务），原来的服务只会 2025-06-18 及以前的握手。现在两代都支持，客户端怎么开口就按哪一代应答。③ **密钥只能写在地址里**：很多客户端是「地址」「请求头 / API Key」分开填的，现在 `Authorization: Bearer <密钥>` 也认。④ **出错时回的是一句中文、状态码也不对**：客户端看不懂，只能报「连接失败」。现在都是 JSON，状态码照规范（缺密钥 401、来源不对 403、地址不对 404、方法不对 405、新协议的各种 400 / 404）。另外把 Streamable HTTP 的客户端指到 `/sse` 的地址、把 SSE 客户端指到 `/mcp` 的地址，现在也都能连上。 |

## 4.1.1 改了什么

| 问题 / 要求 | 做法 |
| --- | --- |
| **导入场景时闪退**（真机：`OutOfMemoryError … growth limit 536870912`） | 崩溃记录里出事的是一个不相干的线程：它只想要 88 个字节，但 512 MB 的堆已经被用光了——用光它的是导入。4.1.0 读 `.blend` 是把整个文件读进内存、解压出第二份、解压用的缓冲区一倍一倍地长又是第三份，打包在里面的贴图再各复制一份留着：一个 300 MB 的场景要一个多 GB，手机上应用总共只有 512 MB。在电脑上把堆限制成 512 MB 复现了：一个 325 MB 的 `.blend`（6 张打包的 4K 贴图、144 万个三角形）在解压那一步就把内存用光。改法：① `.blend` **不再读进堆内存**——没压缩的直接映射文件，压缩的一帧一帧流式解到临时文件再映射；② 打包的贴图解到 `.blend` 旁边的 `<文件名>.tex/` 文件夹，和普通的外部贴图一样按需读（按「贴图上限」缩小）；③ 导入前先量还剩多少内存，**场景比内存放得下的大时只导入放得下的部分，并说明还有多少没导入**，而不是硬撑到应用被杀掉；④ 别的格式（GLB / FBX / PMX…）读之前也先量一下，放不下就直接说"文件太大"，不去硬读；⑤ **贴图排队有了上限**——解码比上传到显卡快，解好的图会排着队等（一张 2K 的图就是 16 MB），4.1.0 这个队没有上限，贴图多的大舞台（不管什么格式）光在这里就能把内存用光；现在排队的图最多 48 MB，满了解码就先等着，内存紧张时把图再缩小一半，实在放不下的那几张不加载、并提示有几张没加载；⑥ 往显卡送顶点数据改成 1 MB 一段地送（以前暂存区和模型一样大，安卓上这一块也算在 512 MB 里）。验证都是在电脑上做的（手头没有那台手机）：只跑"读文件"这一步，堆 512 MB 时这个文件全部读进来（约 5 秒），256 MB 读一半并提示，128 MB 读八分之一并提示；整条流程（读文件 → 建模型 → 送进显卡 → 画一帧）按"堆 416 MB + 直接缓冲 96 MB"跑（合起来 512 MB，安卓上这两样是算在一起的）：导入了 126 万 / 144 万个三角形并提示，6 张 4K 贴图里有 3 张因为内存不够没加载（电脑上的解码器要先按原尺寸整张解出来，比手机上的费内存得多；手机上是边解边缩小），画面正常，没有用光内存；合起来只给 256 MB 时导入 36 万个三角形、贴图都没加载，同样没有用光内存。 |
| 界面默认想要白色的紫罗兰配色，不要黑色的 | 默认整套换成了白底紫罗兰：编辑面板、时间轴、轨道、工具栏都是带一点紫的白纸、深紫色的字；画面的默认背景从深色的「紫夜」换成了浅色的「浅紫」（没有特意换过背景的话，升级之后自动变过来）；压在画面上的字和按钮会跟着背景自动换颜色（亮背景用深紫色、暗背景用白色）；开关、滑杆、选中的片段也从黑色换成了紫罗兰色。想要原来的深色：设置 →「深色界面」，背景在「舞台与背景」里选「紫夜」。还没换的：新手教程每一页左边那块示意动画仍然是深色的。 |

## 4.1 改了什么

| 问题 / 要求 | 做法 |
| --- | --- |
| **闪退**：`maxWidth(-7) must be >= than minWidth(0)` | 出在「编辑 → 轨道」顶上的标尺。标尺上的帧号是用 `drawText(measurer, 字符串, 位置)` 画的，这个写法会按"画布右边还剩多宽"去排版；某个刻度正好落在最右边 3dp 之内时（缩放、滚动、播放中自动滚动都可能碰上），剩下的宽度算出来是负数，直接抛异常。用 4.0.0 的混淆表把崩溃栈还原之后，位置就是 `PlayPanels.kt` 里 `ClipTracks` 的这一句。现在改成先不限宽度把字排好再画上去（`drawLabel`），位置在哪都不会出错；应用里其它在画布上写字的地方（关键帧时间轴、教程）本来就是这种写法。测试里把标尺在各种缩放和滚动位置下都画了一遍，并且确认同样的画法换回旧写法会抛出一模一样的异常。 |
| 入口太多（操控模式就有两个按钮） | 每样东西只留一个入口。**操控模式**只有首页右下角的手柄（菜单里的开关去掉了）。空场景的提示里不再重复放「添加文件」「新建模型」。**角色**页的「添加模型 / 添加整个文件夹 / 从资源库选」并成一行「添加模型」，点进去是同一页：从手机里选文件、选整个文件夹、导入过的模型。**动作与音乐**每个槽行尾那个"选文件"的箭头去掉了（点这一行就是去挑文件），「在轨道上编排」去掉了（轨道在 编辑 → 轨道）。**轨道**的「添加」从五项减到两项。模型页里的「单独调它的物理」「从场景移除」、关键帧菜单和镜头面板里的「导出 VMD」、建模里的「再新建一个模型」、资源库页的两个导入按钮也都去掉了：它们各自在「物理」「角色」「导出」「添加」里已经有了。 |
| 资源库只能加载、不能删除 | 凡是列着导入过的文件的地方（角色 → 添加模型、各个槽的挑文件页、设置 → 资源库），每一行右边都有一个垃圾桶。删模型会连它的贴图一起删（它所在的包里没有别的东西时整包删掉；包里还有别的模型 / 动作时只删模型文件本身，并且会告诉你）。场景里正在用它的模型、音乐、动作片段、脚本也一起移除，不会留下一个下次打开就恢复不出来的场景。删完会告诉你腾出了多少空间。4.0 其实也能删，但藏在「设置 → 资源库 → 点一个文件 → 弹窗最下面」，等于没有。 |
| 片段之间没有过渡 | 轨道里选中后一段，点「过渡」选长度（0.25 秒到 3 秒）：这一段开头的那几帧里，姿势从前一段平滑地变过来（位移和表情线性混合，旋转走球面插值，两头缓中间快）。前一段后面如果还有被裁掉的内容，过渡期间它会接着往下播，是真正的交叉过渡；中间隔着空隙时从前一段最后的姿势过渡。镜头片段同样可以。片段开头会画一个斜角表示过渡的范围；可以撤销，存进工程，导出 VMD 时过渡的那几帧逐帧写进去。 |
| 音乐只有一条、不能裁剪和挪动 | 音乐现在和动作一样是轨道上的片段：可以拖到后面再开始、拖两头只用其中一截（不能拉得比文件长）、切开、复制、删除、撤销，同一首歌可以放好几段，也可以放好几首不同的歌。播放时用两个播放器轮流放：正在响的那一段用一个，另一个提前装好下一段的文件、挪到下一段的起点等着，时间线一到就换过去，不用等跳转；只切了一刀没挪动的两段会一直放下去，中间什么都不做。两段之间的空隙里画面按自己的时钟走。4.0 存的工程（只有一整首从头放）照样读得出来。 |
| 代码框没有高亮和补全 | 写脚本的框现在有颜色（关键字、字符串、数字、注释、应用提供的 `scene` `fx` `time` 这些）。正在输入时上面多一条：前半截是补全——敲 `sc` 给出 `scene`，敲 `scene.` 列出这张表里的东西，`m:` 后面给模型 / 骨骼 / 材质的方法，`m.` 后面给属性，代码里出现过的变量名也会给；一行开头敲 `fu` `fo` `if` 给出整段的写法。后半截是手机键盘上不好找的符号（括号和引号成对地放，光标停在中间）和「缩进」。回车后自动跟上一行的缩进，`then` `do` `function(…)` 后面多缩进一层。补全的内容是从接口说明里读出来的，接口改了它跟着变。 |
| AI 通过 MCP 写 Lua 脚本、执行脚本 | 4.0 已经有 `script_write` 和 `lua_eval`，但用起来不顺，而且有一个真问题：**AI 写进来的脚本，应用重启后就没了**（工程里记的是相对路径，下次找不回文件）。这一版：① 修掉了上面这个问题；② `script_write` 写完会让场景跑一小会儿再回报，运行时才出的错也带回来，出错时整个结果标成出错（AI 一眼知道要改），可以顺手带一张截图（`screenshot: true`）；③ 新增 `script_edit`（只改其中一处，不用把整份代码再发一遍）、`script_run`（运行 / 从头重新运行，脚本库里的也能直接跑）、`script_stop`；④ `lua_eval` 立刻执行一段 Lua，返回的表会展开打印出来（比如一次看到全部骨骼名），出错标成出错；⑤ 工具说明里直接带了一个最小的例子，服务的总说明和应用里的「AI 操作」页都写明了"能写脚本、能运行"。`clips` 工具也能排音乐、设过渡。 |
| 直接导入 `.blend` 这类场景 / 舞台 | 不用再回 Blender 导出一遍：`.blend` 直接读（纯 Kotlin 写的解析器，没有用任何原生库）。读进来的是当前场景里参与渲染的网格物体（父子关系、负缩放、四元数 / 轴角旋转都按 Blender 的算法算位置）、集合实例、共用同一份网格的物体；每个面的材质、UV、平滑 / 平直着色、锐边和「自动平滑」的夹角；材质的基础色、透明度、自发光、粗糙度 / 金属度，以及基础色上连着的贴图——打包在 `.blend` 里的直接取出来，外部的按相对路径去找（只选了一个 `.blend` 时和 `.pmx` 一样回原文件夹把贴图带进来）。2.4x 到 5.3 的文件都能读，包括压缩保存的（2.x 是 gzip；3.0 起是 zstd，安卓没有自带的解压器，自己写了一个）。物体不多时一个物体一个部件，方便在「部件」里一个一个挑。**读不进来的会明说**：镜像和阵列修改器按简单情况展开，其余修改器（细分、倒角、布尔、几何节点……）按修改器之前的形状导入并提醒；曲线 / 文字 / 融球、骨架和动画、从别的 `.blend` 链接进来的东西不导入。详见「已知的不足」。另外 `.vrm` 现在按 GLB 读。 |
| 「部件」里不能删除 | 部件列表每一行右边多了一个垃圾桶。删掉的部件从画面和列表里消失；点「撤销」能找回来，列表底下还有一行「已删除 N 个部件 · 恢复」。删除记在工程里（下次打开还是删掉的），进「建模」或者「另存为 PMX」的时候才真正从模型数据里拿掉（连同空掉的材质，材质表情跟着改号）——所以另存出去的文件和画面上看到的一样。以前「另存为 PMX」不带部件的调整，这一版也一起修了。另外加了「只看它」：别的部件临时藏起来，方便在一大堆部件里看清选中的是哪个。 |
| X / Y / Z、放大缩小要一下一下点，太慢 | 全部换成滑杆，而且**每一根滑杆两头都有减号和加号**：拖是粗调；加减号一下走一小步（位移 0.05、角度 1°、缩放约 2%），**按住不放会连续走**、越走越快；**点右上角的数值**弹出一个自带的小键盘直接输入（不弹系统输入法——横屏时它会盖住大半个画面，数字键盘上还不一定有负号）。位置这类没有上下限的数，滑杆的量程会跟着数值自动放大。用到的地方：「部件」（选中一行，下面展开位移 / 旋转 / 大小三组）、编辑里的「模型」面板（以前只显示数字，不能改）、菜单里模型的那一页、灯光、画面、物理、表情——应用里所有的滑杆都是这一个样子。拖滑杆或者按住加减号时，撤销只记一步。 |

## 4.0 改了什么

| 你提的 | 做法 |
| --- | --- |
| 有音乐时模型卡顿 | 原因：3.0 每一帧都把动作的时间直接设成播放器报的位置，而安卓的播放器报位置很糙（一格一格跳、有几十毫秒抖动），动作时间跟着跳，物理拿到的时间步也对不上。现在画面有自己的平滑时钟，只用最多 ±6% 的速度慢慢贴向音乐，只有差了 0.3 秒以上才直接对齐；物理的时间步和动作走过的时间严格一致；每帧的时间步还会对齐到屏幕的刷新周期。 |
| 去掉音乐延迟设置 | 去掉了。音乐按原样从头放；想让动作晚一点开始，在轨道上把动作片段往后拖。 |
| 像剪辑软件那样的轨道 | 编辑 →「轨道」：镜头、每个角色、音乐、每个脚本各一条。片段可以拖动、拖两头裁剪、分割、复制、删除、撤销；一个角色可以接多段动作，也可以加内置的走、跑、蹲、趴。 |
| Lua 脚本编辑和运行 | 菜单 →「脚本与特效」：新建 / 导入 `.lua` / 11 个示例 / 控制台 / 接口说明。脚本每帧运行，能转骨骼、改表情、改材质颜色和透明度、换上下层、调物理、放粒子和拖尾、新建几何体、接管镜头、加屏幕文字和按钮。关掉脚本后它改过的东西自动复原，也不会被存进工程。 |
| 上下层、透明度 | 每个模型有「层」（层数大的整个盖在层数小的上面，不看远近）和不透明度（半透明时身体里面的面不会透出来）；每个材质还能单独设透明度、颜色、发光。界面上在「角色 → 某个模型」里，脚本里是 `m.layer` `m.opacity` `m:material("裙").alpha`。 |
| 物理参数 | 菜单 →「物理」：重力、风力 / 风向 / 上升气流 / 阵风、重量、弹簧硬度、摆动阻尼、移动阻尼、关节活动范围、碰撞体大小、每秒模拟次数、约束迭代次数、掉帧时补几步、地面；六个一键预设；可以单独调某一个模型。 |
| 简化界面 | 首页只剩四个角：菜单、添加 / 编辑、播放钮（点时间才展开成播放条）、操控和全屏。菜单从 10 项并成 9 项，换成紫色调。 |
| 操控模式 | 首页右下角的手柄：左边摇杆，右边冲刺 / 跳跃 / 下蹲 / 趴下，空白处拖动转视角。走、跑、疾跑、蹲走、匍匐、起跳、落地的动画是按模型的腿长现算的。 |
| 教程 | 重做成 14 页，每页一段动画加几条要点，点页码可以跳到任意一页（「设置 → 新手教程」可以再看）。 |

## 界面

界面的写法参照 [Reze Design](https://github.com/AmyangXYZ/reze-design)（也就是 RezeDesign-Mobile 里装的那个编辑器）：
画面是主角，界面只是压在画面上的几行字。

```
平时                                      点 ☰                                点 ✎ 进入编辑
┌──────────────────────────────┐        ┌───────────┬──────────────────┐    ┌──────────────────────────────┐
│ ☰ 场景名              ✎ [添加] │        │ ‹ 选项  ×  │                  │    │ ☰ ‹完成 轨道 模型 骨骼 表情 … ↶ │
│   动作 · ♪ 音乐                │        │ 角色     › │                  │    │                     │ 工具面板 │
│                              │        │ 动作与音乐 › │      画面         │    │        画面          │        │
│            画面               │        │ 脚本与特效 › │                  │    │  （时间轴 / 轨道）     │        │
│                              │        │ 物理     › │                  │    │                     │        │
│ (▶ 0:12 / 3:38 ^)       🎮 ⛶ │        │ …         │                  │    │ ⏮ ‹ ▶ › [帧] ◆ ⌫ ⧉ …        │
└──────────────────────────────┘        └───────────┴──────────────────┘    └──────────────────────────────┘
```

- **平时**画面占满整个屏幕：左上是菜单和场景名，右上是铅笔和「添加」，左下是一颗播放钮（点旁边的时间展开成带进度线、循环、倍速的播放条），
  右下是操控模式和隐藏界面。
- **菜单**是一张纸面卡片，里面是一行行的列表，点一行往里进一层，左上角返回；点卡片外面的画面它就收起来。
  角色、动作与音乐、脚本与特效、物理、舞台与背景、灯光与画面、导出、AI 操作、设置。每样东西只有一个入口。
- **编辑**（轨道、摆姿势、关键帧、建模）平时不占地方，点铅笔才进去；点「完成」回到干净的画面。
- 横屏时卡片和工具面板靠边放，竖屏时放在下半屏，模型始终露在外面。屏幕方向跟随系统，也可以在「设置」里锁定。
- 一行一条发丝线，滑杆是一根细线加一颗珠子，选中的东西用下划线。带含义的颜色只有三种：紫色 = 选中，琥珀色 = 提醒，红色 = 删除。

## 脚本（Lua）

```lua
-- 让选中的角色半透明、盖在别的模型上面，并在右手上挂一串光点
local m = scene.main()
m.opacity = 0.6
m.layer = 1
fx.emitter{ model = m, bone = "右手首", texture = "spark", rate = 60, life = 0.8 }

function update(dt)                      -- 每一帧调用
  m:bone("頭"):rotate(0, math.sin(time.real * 2) * 15, 0)
  physics.wind(80 + 60 * math.sin(time.real), 0, 0)
end
```

- 完整的接口在应用里的「脚本与特效 → 接口说明」（可以整段复制给 AI）。它是每次打开时当场生成的：通用的接口（源头是 `engine/.../script/ScriptLibrary.kt` 的 `REFERENCE`）
  加上场景里现在真有的模型、骨骼、表情、材质、刚体的名字（`script/ScriptDoc.kt`）。
- 能用的东西：`time` `scene` 模型 / 骨骼 / 材质 / 刚体 `physics` `camera` `light` `post` `fx`（粒子、贴片、拖尾、闪光、屏幕滤色、线）
  `canvas`（自己画贴图）`mesh`（自己搭网格）`sim`（自己做物理）`ui`（文字、按钮、提示）`input`，
  以及 `after` `every` `tween` `run / wait` 这些小工具。
- 沙箱：不能读写文件、不能执行系统命令、不能加载 Java 类；一次调用最多约三百万条指令，死循环会被中止而不是卡死画面。
- 脚本出错会停下来，把「第几行、什么错」写在脚本页和输出里；它改过的东西自动复原。
- 脚本文件放在资源库的「脚本」文件夹里，是普通的 `.lua` 文本。
- 写代码的框有语法颜色、补全条和符号键（见上面「4.1 改了什么」）；也可以不自己写，让 AI 通过 MCP 直接写进来并运行。

### 自己造东西：canvas / mesh / sim

```lua
-- 重画瞳孔：把眼睛原来的贴图铺到画布上，在上面画新的虹膜，再让材质改用这块画布
local m = scene.main()
local eye = m:material("目")                      -- 名字照「接口说明」里列的写
local c = canvas.new(512, 512)
c:image(eye)                                       -- 原图
local u0, v0, u1, v1 = eye:uv_bounds()             -- 这块材质用到贴图的哪一块
local cx, cy = (u0 + u1) / 2 * c.width, (v0 + v1) / 2 * c.height
local r = (u1 - u0) * c.width * 0.3
c:radial(cx, cy, r * 0.2, r, {1, 0.85, 0.2, 1}, {0.8, 0.1, 0.3, 1}); c:circle(cx, cy, r)   -- 虹膜
c:color(0, 0, 0, 1); c:circle(cx, cy, r * 0.35)                                               -- 瞳孔
c:color(1, 1, 1, 0.9); c:circle(cx - r * 0.3, cy - r * 0.35, r * 0.15)                        -- 高光
eye:texture(c)                                     -- 之后再往 c 上画，模型上马上跟着变

-- 倒水：从手上一直喷液体粒子，落在地上、被角色的身体挡开
local w = sim.world{ max = 1500, spacing = 0.4, render = "liquid", color = {0.4, 0.7, 1, 0.8} }
function update(dt)
  local x, y, z = m:bone("右手首"):pos()
  for i = 1, 4 do w:emit(x, y, z, 0, -10, 0) end
end

-- 自己写的物理：内置没有万有引力，就在 on_step 里自己加
local g = sim.world{ gravity = 0, ground = false, collide = false, render = "balls" }
local sun = g:add(0, 10, 0, { mass = 0, radius = 1 })
local p = g:add(8, 10, 0, { vel = {0, 0, 12} })
g.on_step = function(h)
  local x, y, z = g:pos(p)
  local dx, dy, dz = -x, 10 - y, -z
  local d = math.sqrt(dx * dx + dy * dy + dz * dz)
  local f = 1200 / (d * d * d)
  g:force(p, dx * f, dy * f, dz * f)
end
```

| | 是什么 | 能做什么 |
| --- | --- | --- |
| `canvas` | 一块 RGBA 画布（最大 1024×1024，最多 24 块）。纯色 / 线性渐变 / 径向渐变的画笔，叠加、提亮、压暗、滤色、擦除几种混合，圆、环、椭圆、矩形、线、多边形（带抗锯齿和虚边），逐像素读写、`each` 逐像素算，模糊、噪声，把另一块画布 / 材质原来的贴图 / 资源库里的图片铺上来 | 凡是写贴图名字的地方都能用它：`mat:texture(c)` 换掉模型上的贴图（瞳孔、纹身、会动的屏幕、表情贴图），粒子、贴片、脚本网格、液体粒子的贴图 |
| `mesh` | 自己给顶点、法线、UV、顶点色、面的网格（最多 96 个），三角面 / 线 / 点三种画法；有现成的网、球、盒子；每一帧都能改顶点；可以挂在骨骼上；可以直接跟着物理世界的质点走 | 任何形状：水面、地形、披风、光环、轨迹、函数图像、程序生成的道具 |
| `sim.world` | 质点 + 约束的物理世界（最多 8 个、每个最多 6000 个质点）。距离约束用 XPBD（柔度参数不随步长变）；液体用 PBF（密度约束 + XSPH 粘性 + 内聚）；地面、容器、和模型刚体的碰撞、质点互相碰撞；钉在骨骼上；`rope` / `cloth` / `fill` / `emit` 一句话建绳子、布、一缸水、水流 | 头发、绳子、布料、软体、水、沙子、烟花。`on_step` 每个子步回调：脚本自己读写任何质点的位置、速度、力——弹簧、引力、磁场、浮力、涡流、自定义约束都能自己写；`auto=false` + `w:step(dt)` 连节奏都自己掌握 |
| `sim.body` / `sim.joint` | 脚本刚体和关节，和 PMX 模型的头发裙子用的是同一个求解器；盒子 / 球 / 胶囊，自动配一个能看见的网格 | 积木、保龄球、多米诺、链条、布娃娃 |
| `sim.collider` | 脚本自己放的碰撞体，可以跟着骨骼 | 给手上加一个能挡水、能推布的球；桌子、墙 |
| `sim.raycast` / `sim.distance` | 射线和最近距离查询（地面、模型刚体、碰撞体、脚本刚体） | 让东西落在脚下、判断手有没有碰到、自己写的物理里做碰撞 |

脚本停掉（或出错）时，它建的画布、网格、物理世界、刚体全部自动清掉，材质换回原来的贴图。
内置示例里有五个用到这些的：重画瞳孔、倒水、布料披风、自己写的物理、积木。

## 添加文件

点右上角的「添加」，在手机里选文件，**可以一次选好几个**，应用按内容把它们各自放好：

| 选了什么 | 放到哪 |
| --- | --- |
| 模型（`.pmx` `.pmd`，或者整个 `.zip`；也支持 Blender 的 `.blend`、glTF / GLB / VRM / FBX / OBJ / STL / PLY / `.x`） | 加进场景（「角色」）；场景、舞台这类大的东西自动归到「舞台」 |
| 身体动作 `.vmd` | 选中角色的「动作」槽 |
| 只有表情 / 口型的 `.vmd` | 「表情」槽：叠在身体动作上，替换掉动作自带的表情轨道 |
| 镜头 `.vmd` | 「镜头」槽 |
| 音乐（mp3 / wav / ogg / m4a / flac …） | 「音乐」槽（换掉原来的，从头放），播放时以音乐为主时钟；想放好几段或者只用一截，在轨道里排 |
| 姿势 `.vpd` | 套到选中的角色上 |

这些槽都在菜单的「动作与音乐」里：每个槽右边的箭头是换一个文件，叉是清空，点这一行可以从导入过的文件里挑。
下面的「排布」可以让某个角色的动作晚几帧开始、让音乐早一点或晚一点开始，把它们对齐。
一个 zip 里有好几个模型时会问加载哪一个。从文件管理器「打开方式」「分享」发给本应用也是同样的处理。

### 只选了一个 .pmx 时的贴图

PMX 按相对路径找贴图，贴图在它旁边的文件夹里。用系统的文件选择器只选一个 `.pmx` 时，Android 只把这一个文件交给应用，
所以应用会**回它原来的文件夹，把模型用到的贴图一起导入**（只带模型引用的那些文件，不会把整个文件夹搬进来）：

- 有「所有文件访问权限」时全自动：从选中文件的 Uri 推出它在手机里的真实路径，直接去那个文件夹里读。
- 没有权限时弹出「贴图没有一起导入」，两种办法选一种：
  - **允许访问所有文件**：跳到系统设置页开一次，以后都自动；
  - **选择模型所在的文件夹**：系统的文件夹选择器会停在那个文件夹上，点「使用此文件夹」即可，只授权这一个文件夹。
- 点了「先不管」的，之后在「角色」里会标着「缺 N 张贴图」，点进去可以再找。
- 大小写不一致、路径写成作者电脑上的绝对路径、贴图在上一层文件夹里（`..\tex\a.png`）、扩展名被转换过（`.tga` → `.png`）都能找到；
  日文压缩包解压后文件名变成乱码的贴图也能对上。
- OBJ 的 `.mtl`、分开存的 glTF 的 `.bin` 也是这样带进来的。

选整个 zip、或者在「角色」里点「添加整个文件夹」不需要任何权限。

## 让 AI 操作（MCP）

菜单 →「AI 操作」→ 打开开关，界面上会显示两个地址：

- `http://<手机的 IP>:8765/mcp/<密钥>`：Streamable HTTP，现在的客户端都用这个（有的客户端里这一项叫 HTTP）
- `http://<手机的 IP>:8765/sse/<密钥>`：旧的 HTTP+SSE，只有 SSE 可选的老客户端用这个

把地址（或者面板里给的整段 JSON 配置）填到支持 MCP 的 AI 客户端里，手机和电脑连同一个 Wi-Fi。
AI 客户端就装在这台手机上时，用面板里 `http://127.0.0.1:8765/mcp/<密钥>` 那个本机地址。

**可以切到别的应用（4.2）**：开着 MCP 时通知栏里有一条「MCP 服务运行中」，应用在后台也会马上应答，AI 照样能截图、建模、跑脚本。
后台时画面不会自己往前走（系统不给后台应用画画面），AI 用 `advance` 工具推进时间；想边聊边看就用分屏或小窗。
如果切走以后 AI 客户端还是要等很久才连上：看面板上的「已收到 N 条请求，最近一条处理用了 X 毫秒」——这个数很小而客户端等了很久，
说明请求是被系统拦在了路上，点面板上的「允许后台运行（不限制电池）」；部分手机还要在系统的「应用启动管理 / 自启动 / 后台限制」里放行本应用。
客户端要求「地址」和「密钥 / 请求头」分开填的，地址填 `http://<手机的 IP>:8765/mcp`，请求头填 `Authorization: Bearer <密钥>`
（面板里也有这种写法的整段配置；`X-API-Key: <密钥>` 和 `…/mcp?token=<密钥>` 也认）。
只会 stdio 的客户端（比如 Claude Desktop）可以用 `npx mcp-remote http://<手机的 IP>:8765/mcp/<密钥> --allow-http` 转接。

除了这两个，同一个端口上还有（4.1.3）：

| 接法 | 地址 | 说明 |
| --- | --- | --- |
| WebSocket | `ws://<手机的 IP>:8765/ws/<密钥>` | 每个文本帧是一条 JSON-RPC 消息（先 `initialize`，和旧版本握手方式一样），应答各用一帧发回。把 `/mcp/<密钥>` 的地址直接换成 `ws://` 来连也行；客户端要 `mcp` 子协议时会照着回 |
| 普通 HTTP | `GET  http://<手机的 IP>:8765/api/<密钥>/tools` | 工具清单，OpenAI 函数调用的格式（`{"type":"function","function":{name, description, parameters}}`），可以直接塞给任何支持函数调用的模型；`?format=mcp` 给 MCP 的原样 |
| | `POST http://<手机的 IP>:8765/api/<密钥>/tools/<工具名>` | 请求体就是参数对象。应答 `{"ok":true,"text":"…","image":{"mimeType":"image/png","data":"<base64>"}}`；`ok=false` 是工具自己报的错，原因在 `text` 里 |
| | `GET  http://<手机的 IP>:8765/api/<密钥>/openapi.json` | OpenAPI 3.1 描述，每个工具一个操作：Open WebUI 之类的「OpenAPI 工具服务器」、能导入 OpenAPI 的平台填这个 |
| stdio | 桌面版：`… McpMain --stdio lib=<资源库>` | 一行一条 JSON-RPC，标准输出只有协议消息（日志走标准错误）。手机上没有 stdio 可言，用上面的 `mcp-remote` 转接 |

密钥的给法各处都一样：写在路径里，或者 `Authorization: Bearer <密钥>` / `X-API-Key` / `?token=`。

```bash
# 不用任何 MCP 客户端，直接用 curl 让角色抬手再截一张图
curl -s http://192.168.1.23:8765/api/<密钥>/tools | head -c 300
curl -s -X POST http://192.168.1.23:8765/api/<密钥>/tools/script_api -d '{"limit":40}'
curl -s -X POST http://192.168.1.23:8765/api/<密钥>/tools/lua_eval -d '{"code":"scene.main():bone(\"右腕\"):rotate(0,0,-60)","screenshot":true}'
```

### 兼容性

服务在 `engine/…/mcp/McpServer.kt`，纯 Java 套接字写的，没有用任何库，按 MCP 规范实现：

| | |
| --- | --- |
| 协议版本 | 2026-07-28（无状态：没有握手和会话，每个请求在 `_meta` 和请求头 `MCP-Protocol-Version` / `Mcp-Method` / `Mcp-Name` 里带着版本、方法、名字；`server/discover` 查询服务；应答带 `resultType`，清单带 `ttlMs` / `cacheScope`）；以及先 `initialize` 握手的 2025-11-25、2025-06-18、2025-03-26、2024-11-05。同一个地址两代都支持，客户端怎么开口就按哪一代应答 |
| 传输 | Streamable HTTP（`POST /mcp`，应答是 `application/json`；客户端只收事件流时包成一条 SSE 消息）；旧的 HTTP+SSE（`GET /sse` + `POST /messages`） |
| 会话 | 不保存会话，不发 `Mcp-Session-Id`：应用重启、换了网络之后客户端不用重连。`GET /mcp`（要「服务端主动推送」的流）和 `DELETE /mcp` 回 405，规范允许 |
| 密钥 | 地址里（`/mcp/<密钥>`）或请求头里（`Authorization: Bearer`）。没带回 401 + `WWW-Authenticate`，地址里的密钥不对回 404。没有 OAuth，`/.well-known/oauth-*` 回 404 |
| 浏览器 | 检查 `Origin`：只接受本机 / 局域网里的页面和桌面应用自己的页面，外面网站上的页面回 403（防 DNS rebinding，规范要求）。不是浏览器的客户端不发这个头，不受影响 |
| 工具 | 只声明了 `tools`。没有这个工具、参数不是对象是协议错误（-32602）；工具自己执行失败是正常应答里带 `isError`，AI 看得到原因。参数表只用各家模型都收的写法（见 4.1.2 的说明） |

连过并且能取到工具清单、能调工具的客户端（`McpServerTest` 之外，在电脑上的调试宿主上实际跑的）：
官方 Python SDK `mcp` 2.3（自动 / 只用 2026-07-28 / 只用握手 / 旧 SSE）、TypeScript SDK 1.32（Streamable HTTP、SSE）、
新的 TypeScript 客户端 `@modelcontextprotocol/client` 2.4（自动 / 只用 2026-07-28 / 只用握手）、MCP Inspector 2.16（新协议、Bearer、SSE）、
`mcp-remote` 0.16（各种传输策略、Bearer）；官方一致性测试 `@modelcontextprotocol/conformance` 里适用的几项（握手、ping、工具清单、DNS rebinding 防护）都通过。
各家 AI 应用（Claude、Cursor、Cherry Studio 等）本身没有逐个装来试；它们大多是基于这些 SDK 做的。

之后直接对 AI 说"让她挥挥手""做一张小桌子""写个脚本让她的头一直跟着镜头转"就行。一共 48 个工具：

- 看：`get_scene` `list_library` `list_bones` `list_morphs` `get_pose` `get_keys` `mesh_info` `screenshot`（AI 可以自己截图看效果）
- 场景：`load_model` `remove_model` `set_model` `set_camera` `load_motion` `save_project`

### AI 写脚本、运行脚本

AI 的一轮通常是这样（下面是在电脑上的调试宿主里真的跑过的一段，画面见 `release/screenshots/mcp_lua_script.jpg`）：

```
script_api {}                                         → 接口全文（只要读一次）
lua_eval {code: "return scene.main():bones('腕')"}     → => {<bone 28 "左腕">, <bone 29 "左腕捩">, … <bone 64 "右腕">, …}
script_write {name: "挥手", code: "...", screenshot: true}
        → {"running":true, "error":null, "log":["[挥手] 开始挥手\tHutao"], "saved_as":"脚本/挥手.lua"} + 一张截图
script_edit {script: "挥手", find: "m:morph(\"笑い\", 0.8)", replace: "m:bone(\"没有这根骨\"):rotate(1,2,3)"}
        → 出错（isError）：{"running":false, "error":"第 10 行：在一个 nil 上取成员（前面那个东西是空的，比如没找到的骨骼 / 模型）", "hint":"…"}
script_edit {…改回来…}                                 → {"running":true, …}
script_stop {script: "挥手"}                           → 脚本改过的东西全部复原
```

- `script_write`：先查语法（语法错什么都不动），再存进脚本库、放进场景、启动，让场景跑 `seconds`（默认 0.3 秒）之后回报：`running`、`error`（带行号）、这段时间新出的 `log`（`print` 的输出）。出错时整个结果标成出错。`screenshot: true` 顺手带回一张截图。
- 写进来的脚本和你自己写的完全一样：出现在「脚本与特效」里，可以点进去看和改，存进工程，下次打开应用还在运行。
- `lua_eval` 是一次性的：在控制台环境里立刻执行，返回值打印出来。它做的改动是临时的，不存进工程。
- `print` 和返回值里，表会展开写出来（`print(m:morphs())` 直接看到全部表情名），模型 / 骨骼 / 材质这类对象写成 `<bone 19 "頭">`，不再是一串 `table: 2e4b8173`。你自己在应用里写脚本时也一样。
- 脚本出错、被停掉或被删除时，它改过的一切自动复原，所以 AI 试错不会把场景弄乱。

注意：

- 密钥就是密码，知道它的人都能操作这个应用。只在信得过的网络里开，不用时关掉；面板里可以换密钥。
- 模型、骨骼、表情、材质、脚本这些「序号或名字」的参数，参数表里写的是字符串：名字直接写，序号写成 `"3"`（直接给整数 3 也认）。
  把模型从骨骼上解下来用 `set_model {detach: true}`；`mesh_add_primitive` / `mesh_transform` 的 `scale` 是数组，`[2]` 表示三个方向一样；
  关键帧的 `curve` 写名字，或者四个数写成 `"20,20,107,107"`。
- 应用要开在前台（切到后台后渲染线程停了，工具会报错）。开着 MCP 时屏幕不会自动熄灭。
- AI 改的关键帧、在轨道上做的改动（片段、音乐、过渡）可以用界面上的「撤销」撤回。

## 已知的不足

- **4.2 的后台保活没有在真机上验证过**。「MCP 慢」的原因是按现象（等一分钟才连上、才拿到工具清单）和代码推断的：服务端每一步都是毫秒级，
  唯一能让请求等上几十秒的是应用在后台被系统暂停。前台服务、后台借用 GL 上下文都是照安卓的文档写的，测试环境（JVM）验证不了系统的后台策略。
  如果装了 4.2 还是慢，请看 MCP 面板上的请求统计并告诉我机型和系统版本。
- **碰撞按模型没有动作时的形状算**：带骨骼动画的角色设成「网格」碰撞时，挡东西的是它 T 字站立时的形状（跟着位置 / 旋转 / 缩放走，不跟着骨骼动）。
  角色的身体要挡东西请用它自带的刚体（PMX 模型都有）。网格碰撞是单面的，从背面钻进去 0.8 以上的东西不会被推出来；超过 60 万个三角面的模型退回成包围盒。
- **操控模式里的角色**和带碰撞的模型之间是简化的处理：脚下取最高的面（能上不超过 4 个单位高的台阶），腰的高度放一个球挡墙；很窄的缝、很低的顶不准。
- **三渲二**是在光照上分级 + 描边，没有做法线平滑描边、脸部阴影贴图（SDF）这类更细的东西；需要的话可以告诉我。
- **4.0 和 4.1 新做的部分还没有在真机上跑过**（4.1 修的那个闪退是按你发来的崩溃记录、用 4.0.0 的混淆表还原出位置后改的，并在测试里复现了同一个异常）。 界面是在 JVM 上（Robolectric）测试并截图检查的，三维画面（粒子、上下层、半透明、走跑的姿势）是在电脑上用 Mesa 软件渲染器检查的。
  `release/screenshots/` 里的界面图是 JVM 上渲染的真实界面，中间的三维画面是电脑离屏渲染后垫进去的，不是真机截图。
  4.1.1 起这些界面图是白底紫罗兰的新样子；`blend_classroom` `blend_vs_blender` `engine_*` `mcp_built_table` `mcp_lua_script` `clip_crossfade`
  这几张是引擎直接渲染的旧图，背景还是以前的深色。
- **音乐同步是用模拟验证的**：测试环境不能播放声音，所以是模拟一个位置又糙又抖的播放器来检查画面不跳。真机上如果还觉得不顺，请告诉我机型和音乐格式。
- **走跑的动画是程序算出来的关键帧**，只在一个模型（胡桃）上看过姿势，不如手调的动作自然；模型需要有标准的 MMD 腿部骨骼（足ＩＫ 等），否则只能平移。
- 发布版里 LuaJ 整包保留、不让 R8 改动，但发布版本身没法在这里运行，只验证了调试版。
- **找贴图依赖系统的行为，下面这些只能在真机上确认**：
  - 从 Uri 推真实路径：系统「文件」应用给的 Uri 有测试覆盖；各家文件管理器「打开方式」给的 Uri 写法不一，只按常见的几种写法猜，猜不出来时会退回到「选择模型所在的文件夹」。
  - 「选择模型所在的文件夹」这条路在测试里是对着一个假的文件提供方跑的，系统自带的「文件」应用和各家云盘、文件管理器的实际表现没有验证过。
  - Android 11 以后系统不让授权「下载」文件夹本身和存储的根目录：模型直接放在这两个位置时只能用「允许访问所有文件」。
- **音乐轨道的换段只用假的播放器验证过**：逻辑（提前准备下一段、到点换过去、切开没挪的两段不停顿）有测试，但真机上两个播放器交接时会不会有一下很短的停顿或者重叠，要在手机上听了才知道。
  两段音乐之间是直接切换，没有淡入淡出，也不能调每一段的音量；两段音乐不能叠在一起同时响。
- 过渡：只混合骨骼的位移 / 旋转和表情；IK 的开关不做混合，按后一段的来。过渡最长 3 秒。
- 脚本：补全是按名字给的，不知道变量是什么类型（`m.` 后面给的是所有对象属性的合集）；没有查找替换、没有多级撤销（只有「还原」到上次保存）。粒子是 CPU 上算的，一个发射器最多 6000 颗。
- 和 Reze Design 比还没有的：视频导出、由歌词生成口型、游戏风格的渲染预设和材质节点图、发布成链接。
- 物理不是 Bullet，头发和裙摆的摆动和 MMD 原版不会完全一样。
- **`.blend` 是当成静态的场景读的**，下面这些读不进来（Blender 里它们是打开文件之后现算的，文件里没有结果）：
  - 修改器：只处理「镜像」（以物体自己为中心）和「阵列」（固定数量、固定 / 相对偏移），而且是"再摆几份"，不合并接缝上的点。
    其余的——表面细分、倒角、实体化、布尔、几何节点……——按加修改器之前的形状导入，模型页上会写明有几个物体受影响。
    依赖表面细分的模型（比如官方的 BMW 演示文件）进来是没细分的粗模，零件之间还会互相穿出来。想要一模一样，需要在 Blender 里应用修改器之后再保存。
  - 曲线、文字、融球、毛发、粒子；骨架和动画（按存盘那一刻的位置导入；挂在骨骼上、带约束的物体，4.2 以后的文件里位置可能不对）。
  - 从别的 `.blend` 链接进来的东西（官方的 classroom 演示里桌椅就是这样，进来只有房间）。
  - 材质只认「原理化 BSDF / 漫射 / 自发光」这几种着色器的基础色、透明度、自发光和基础色上连着的图片；贴图坐标的缩放（映射节点）、
    法线贴图、程序纹理、顶点色都不读。EXR / HDR / TIFF 格式的贴图解不了。
  - 灯光和相机不导入。超过 400 万个三角形的场景后面的物体不导入。
  - 验证范围：四个版本（2.79 / 3.6 / 4.2 / 5.3）用自己生成的场景和 Blender 的结果逐项核对过；另外手工试了 assimp 测试集里 2.48–2.93 的二十来个文件
    （含一个大端 32 位的）、Poly Haven 的 8 个模型（2.93 / 3.0 / 4.0 / 4.1）和 Blender 官方的 classroom、BMW 演示文件，都能读、画面对。
    4.1.0 在真机上导入大场景时闪退（内存用光），4.1.1 改了读法（见上面「4.1.1 改了什么」）；改完之后是在电脑上把堆限制成和那台手机一样的 512 MB 验证的，
    **还没有在手机上再试**。手机上一个场景大约只放得下一百多万个三角形（按当时剩余的内存算），超出的部分不导入、会提示。
    压缩保存的 `.blend` 导入时要在应用的缓存目录里临时解开一份（和解压后的文件一样大，用完就删），手机剩余空间不够时会提示。
- `.blend` 以外的格式仍然是整个读进内存的：GLB / FBX 之类的场景超过一百多 MB 时会直接提示"文件太大"（不会闪退，但也读不了）。
- 文本格式的 FBX、Collada（`.dae`）、`.3ds`、USD 仍然读不了。
- 部件的「删除」是记在工程里的标记：部件列表之外的地方（比如模型页的面数）还按原来的算，进建模或者另存为 PMX 时才真正去掉。
- STL / PLY 没有朝向信息，按 Z 轴向上处理；方向不对时在「角色」里点进模型，用「立起来」。
- 关键帧：补间曲线只有四种预设，不能手动拖曲线；一次只能操作一帧，不能在时间轴上框选一片关键帧。
- 导出 PMX 时不保存追加 UV1–4、Flip / Impulse 表情和软体；多于四边的面存盘后会变成三角形和四边形。
- 建模没有贴图绘制和权重绘制：绑骨骼是"把选中的部分整个绑到一根骨骼"。
